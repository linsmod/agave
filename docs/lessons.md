| R17 经典 `<script defer src>` 不再卡解析（2026-11-04 已修） | 现象：deepseek 的 `main.js`（`defer`）在 `<body>` 建出来之前就跑了（`document.body` 为 null）。原实现把它塞进 `pendingScripts` 等待位，等于同步阻塞解析 → 脚本在 `<head>` 阶段执行。改成与 `async` 同一条投递路径：tokenizer 认出 `deferScript` 走非阻塞 `CachedScript`，`HTMLScriptElement::evaluateScript()` 里 `defer() && !async` 就 `queueDeferredScript()` 交给解析后 flush（按文档顺序）。**踩到的两个坑**：①**桥接的文档绑定会滞后**——`bindDocument()` 在 `kjs_proxy` 每次求值前调用，而延后求值是直接从资源回调进的，此时 `g_document` 还停在帧的初始 `about:blank`（脚本里 `document.body` 为 null、`document.title` 写了个空文档、`getElementById` 全 null）；②flush 的"已封口"标志原来按 **realm 代**记录，而初始空文档与真页面**共用一代** → 空文档的 DOMContentLoaded 就把队列封了，真页面的 defer 脚本全走"立即执行"分支。修法：`flushDeferredModules(void* document)` 按 **document** 记录封口（无 `body()` 的空文档不封），队列项记住自己的 document，执行前先 `bindDocument()` 对齐 | 验证（新增回归页 `debug/defercheck.html` + `defercheck.js`）：`window.__deferSeen` = `url=file:///.../defercheck.html body=1 ... out=1 ready=complete`，`#out` 被改写、`title=DEFER-OK`（都在解析后）；阻塞式 `<script src>` 对照组仍 `body=0`（解析期内执行，顺序语义未变）；`AGB_OFFLINE=1` 重放 browserscore 模块图 `kids=3 title=Browser Score` 无回归；beforeunload/csscheck/newtab/form 全绿 |

| R13 hover 时内容随机消失/被纯色遮挡（2026-11-03 已修） | 现象：鼠标移到链接/结果标题上（`:hover` 变色）时该行内容"变没"或出现纯色块。两个根因都在 rect 计算：**A. inline flow 的重绘矩形是 0×0** —— `RenderFlow::absoluteClippedOverflowRect()` 在 `isInlineFlow()` 分支里用 `width()/height()` 作矩形尺寸，但移植版本里**没有任何地方对 RenderFlow 调 `setWidth()/setHeight()`**（`RenderFlow.cpp`/`RenderInline.cpp` 全文无此调用），m_width/m_height 恒为 0 → 重绘脏区退化成一个点 → hover 变色不触发重绘，旧文字像素留着；一旦背景重绘擦掉该区域，文字就再也不画回来（"被纯色遮挡"）。**B. `clip()` 是替换语义而非求交** —— `GraphicsContext::clip(const IntRect&)` 用 `ps_scissor_rect`，picasso 的实现是 `ctx->state->clip.type = clip_device; clip.rect = tr;`（整块替换，`_clip_path` 的交集被丢弃），而 WebKit 的 `clip(rect)` 语义是与当前裁剪求交：父级 overflow 裁剪会被子元素自己的 clip 覆盖 → 子元素画到自己盒子之外（背景横向"溢出到同一行"）。修法：A 改成取所有 line box 的并集（`left/top/right/bottom` 由 `curr->xPos()/yPos()/width()/height()` 累出）；B 改用 `ps_clip_rect`（走 `_clip_path` 的 `clip_intersect`，且 `ps_save/ps_restore` 本来就会恢复）—— **⚠ B 项的修法本身是错的，已由 R14 推翻**（`ps_clip_rect` 收的是世界坐标，这里传的是设备坐标 → rect 被变换两次 → 滚动时裁剪区整体平移，屏幕下半段不重绘）。 | 验证：`debug/csscheck.html` 全绿（除已知未实现的 grid/transform/sticky/aspect/gap），用户实测 hover 不再丢内容；辅助页 `debug/hovercheck.html`（inline `:hover` 变色）、`debug/clipcheck.html`（三层嵌套 `overflow:hidden`）、`debug/hoverprobe.ps1`/`mousescan.ps1`（真实鼠标 + PrintWindow 像素对比） |

## 附：怎么写新条目

1. 标题带编号与日期：「R25 <一句话现象>（YYYY-MM-DD 已修）」。
2. 「现象 · 根因 · 修法」写**代码锚点**（文件:行号或函数名），不要只写「改好了」。
3. 「验证」写**可重跑的判据**（探针命令 + 期望输出 + 回归页），不要只写「测试通过」。
4. 修法后来被推翻时别删旧条目：在新条目里写「⚠ 推翻 R<n> 的 X 项」——这种前后矛盾本身就是最值钱的经验。
